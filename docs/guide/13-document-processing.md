# Document Processing (Detailed)

Documents are ingested by **document_processor.py** and triggered by **watcher.py** when files appear or change in the `documents/` folder.

## Supported Formats

- PDF, DOCX, TXT, CSV, XLSX, XLS, MD.  
- Extensions and max file size (e.g. 10 MB) defined in document_processor (SUPPORTED_EXTENSIONS, MAX_FILE_BYTES).

## Pipeline (Phase 3: Parent-Child)

1. **Load**  
   File is read (e.g. PyPDF, python-docx, openpyxl, unstructured) into raw text.

2. **Parent chunks**  
   Text is split with RecursiveCharacterTextSplitter (chunk_size 2000 tokens, overlap 200). Each chunk is inserted into **parent_chunks** (content, metadata, file_id, chunk_index). No embedding for parents.

3. **Child chunks**  
   Each parent is split again (chunk_size 500 tokens, overlap 50). Children are tokenized and embedded in batches (OpenAI text-embedding-3-small). Each child is inserted into **documents** with content, metadata, embedding, file_id, chunk_index, **parent_id** (FK to parent_chunks). The `fts` column is generated by PostgreSQL from content.

4. **File record**  
   **files** table: filename, file_type, file_size, chunk_count, status (processing → ready or error), error_message (on failure). Updated when processing completes.

5. **Re-processing**  
   On file change or re-add, existing rows for that file are deleted (documents by file_id, parent_chunks by file_id), then the pipeline runs again. Watcher uses hashing to avoid re-processing unchanged files.

## Watcher

- **watcher.py** uses the **watchdog** library to monitor `documents/` (or path from config).  
- On create/modify: enqueue or trigger document processing.  
- On delete: remove file record and associated chunks from DB.  
- Runs in a background thread; started in FastAPI lifespan.

## Metadata

- Parent and child metadata include source filename and file_id.  
- Child metadata flows to Document in retrieval; _doc_to_source uses metadata.source (or filename) and chunk_index for the Sources UI.

## Errors

- If processing fails, files.status is set to "error" and error_message stored.  
- Frontend DocumentList shows status and optional error; backend list_files returns these.
